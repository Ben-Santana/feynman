# Refined evaluator and learner in normal conversations

The normal `/api/chat` path now uses a simplified refined primary with the same deterministic validation rules as the evaluator developer tool. Exact evidence citations and every rubric item plus the level task control progression. No legacy confirmation or experimental shadow call runs in normal conversations. Developer comparisons retain their explicit legacy baseline and opt-in shadow/ablation modes.

`refinedEvaluator.js` shares material construction with the comparison tool. The normal primary uses a shorter prompt and shared schema for ordinary items, with one overall rationale instead of repeated per-item rationale. Detailed independence, transfer and component policies retain their required fields. Developer ablations retain their existing lean prompt/schema. Its conversation adapter preserves the existing checklist, progress, grade and summary response fields, while retaining the full validated assessment under `assessment.refined`. It maps unclear to the UI's existing needs-clarification status; it never recomputes a more permissive completion decision.

For unfinished ordinary stages, `strategyLearner.js` derives diagnostic state from the already validated rubric assessment, retrieves reviewed strategies, selects a grounded plan, and generates one question. There are no separate diagnosis, plan-review or question-review model calls. The selector also receives the rubric assessment. Code still checks strategy eligibility, plan structure and exact learner grounding, and rejects empty, oversized, repeated, generic or known leading question wording. These checks do not provide semantic clarity or domain-suitability review. Developer comparisons use the same pipeline. Missing strategy coverage or rejected plans/questions use the ordinary rubric-based generator, without first spending a call on an unused baseline question. The diagnostic state and applied strategy are returned as `learnerModel` and saved with the concept; they are cleared at a level transition. They cannot override rubric completion.

Opening turns retain the existing opening/scenario behavior. Quantitative Analyze retains its worked-paper, review, explanation and report flow, with refined evaluation after the explanation. The strategy pipeline does not replace paper generation or paper-review acknowledgement.

These are runtime defaults, not client-selectable assessment modes. Client fields cannot switch the main API back to legacy evaluation or enable shadow. The selected provider/model remains controlled by the existing AI settings.

After pulling upstream main (`75fbd55`), developer requests use the account-authenticated transport and retain admin-only access. The evaluator and strategy CLI tools require an active admin access token in `FEYNMAN_ACCOUNT_TOKEN`; the removed four-digit access-code endpoint is no longer used. Tokens are not saved to result archives.

A successful unfinished ordinary turn now uses **three model calls**: one rubric evaluation, one strategy selection/planning call, and one question-generation call (previously six). Retries and fallback attempts can add calls. Completed ordinary stages stop after the rubric assessment. Openings and quantitative paper flows retain their existing behavior. No new live-model accuracy or latency claim is made for this change.

Human-rated held-out conversations, expert adjudication and independent evaluation of learning gains remain deferred. The previous authored-fixture results do not establish educational validity; activation here follows the user's explicit request.
