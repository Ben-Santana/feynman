# Refined evaluator and learner in normal conversations

The normal `/api/chat` path now uses a simplified refined primary with the same deterministic validation rules as the evaluator developer tool. Exact evidence citations and every rubric item plus the level task control progression. No legacy confirmation or experimental shadow call runs in normal conversations. Developer comparisons retain their explicit legacy baseline and opt-in shadow/ablation modes.

`refinedEvaluator.js` shares material construction with the comparison tool. The normal primary uses a shorter prompt and shared schema for ordinary items, with one overall rationale instead of repeated per-item rationale. Detailed independence, transfer and component policies retain their required fields. Developer ablations retain their existing lean prompt/schema. Its conversation adapter preserves the existing checklist, progress, grade and summary response fields, while retaining the full validated assessment under `assessment.refined`. It maps unclear to the UI's existing needs-clarification status; it never recomputes a more permissive completion decision.

For unfinished ordinary stages, `inlineQuestionStrategies.js` supplies level-eligible, design-reviewed catalog rules to the existing focused response call. That call chooses a strategy and generates the question together. The structured response includes a brief rationale, an exact current-stage learner quote, and one active rubric item. Code validates eligibility and grounding, plus the existing question wording safeguards. An explicit `none` choice asks the focused rubric question in the same call and records a coverage-gap reason. Selection is saved in `learnerModel` with `selectionMethod: inline_response` and diagnostic state derived from the assessment; it cannot override rubric completion. It does not include a separately validated plan or establish semantic suitability. Developer strategy comparisons retain the separate selector/planner and fuller example context in `strategyLearner.js`.

Opening turns retain the existing opening/scenario behavior. Quantitative Analyze retains its worked-paper, review, explanation and report flow, with refined evaluation after the explanation. The strategy pipeline does not replace paper generation or paper-review acknowledgement.

These are runtime defaults, not client-selectable assessment modes. Client fields cannot switch the main API back to legacy evaluation or enable shadow. The selected provider/model remains controlled by the existing AI settings.

After pulling upstream main (`75fbd55`), developer requests use the account-authenticated transport and retain admin-only access. The evaluator and strategy CLI tools require an active admin access token in `FEYNMAN_ACCOUNT_TOKEN`; the removed four-digit access-code endpoint is no longer used. Tokens are not saved to result archives.

A successful unfinished ordinary turn uses **two model calls**: one rubric evaluation and one combined strategy-selection/question-generation call. Completed stages stop after evaluation. Retries can add calls; exact scoped retries can reuse a cached evaluation. Catalog input and choice output add tokens, so unchanged call count does not establish unchanged latency. Openings and quantitative paper flows retain their existing behavior. No new live-model accuracy or latency claim is made.

Human-rated held-out conversations, expert adjudication and independent evaluation of learning gains remain deferred. The previous authored-fixture results do not establish educational validity; activation here follows the user's explicit request.

## Background knowledge bridge

`background-knowledge-bridge` asks one prerequisite question, then reconnects the answer to the harder task. It runs inside ordinary response-side selection without another model call. The active rubric and level stay fixed; `probeLevel` records the temporary simpler demand. Assistant-message `background` metadata persists the original stage-local question index, learner evidence, prerequisite, return target, phase, and probe count in both learning chats and Chat Workshop. Stage transitions clear the active detour; Quantitative Analyze may retain old messages as inactive history without interpreting their stage-local indices as an Analyze probe.

At most two probes are allowed in one detour, and a rubric item cannot start another detour in the same stage. Generation must return or exit a pending detour instead of silently dropping it. A prerequisite-help request closes the detour and retains assistance provenance. Remember and the Quantitative Analyze paper flow are excluded from initial eligibility.

Evaluation receives the offered opportunity and original task alongside the transcript. After a background probe, `backgroundResponseScope` distinguishes prerequisite-only answers from volunteered original-task reasoning. Completion is blocked unless original-task demonstration is explicitly reported with a real latest-response quote also represented in the task evidence. All ordinary citation, reasoning, independence, and transfer gates still apply; this scope check is not independent semantic validation.

Examples and implementation verification are described in [the plan](background-question-strategy-plan.md) and the local `output/background-strategy-live-2026-11-02.md` report. The three new fixture rubrics are authored and labeled accordingly, rather than presented as generated rubrics.
